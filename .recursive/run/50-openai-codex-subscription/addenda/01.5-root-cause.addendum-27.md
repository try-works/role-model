## Root Cause

`runtime:validate-ui` no longer stalls at startup, but it still does not terminate after printing
its result payload. Inspection of the live process tree showed:

1. `src/validate-ui.ts` completed its validation flow and printed the JSON result
2. the script only called `server.close()` in `finally`
3. the runtime backend created by `createRuntimeBridgeBackend(...)` was never shut down
4. the managed `llama-swap.exe` child therefore stayed alive and kept the Node process from
   exiting

So the blocker is not the validation scenario itself anymore. It is missing backend teardown in the
validator cleanup path.

## Evidence

- live `corepack pnpm run runtime:validate-ui` output reached the final JSON payload but the
  process remained running
- `Get-CimInstance Win32_Process` showed a surviving child `llama-swap.exe` under the validator
  Node process
- `/role-model-router/apps/runtime-host-bridge/src/validate-ui.ts` only closed the HTTP server in
  `finally`
