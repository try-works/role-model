Scope note: This addendum records the remaining live routing collapse after the role-binding and controller-output fixes: controller quality requests still score from generic latest profiles instead of difficulty-aware profile slices, and controller endpoint rankings can bias routing even when they merely restate the full candidate pool.

## Error Analysis

Live `controller.remote-only` requests now execute successfully, but harder controller-selected quality requests still collapse onto `deepseek-v4-flash` even when:

1. the controller emits `strategy = "quality"`
2. all remote candidates remain eligible
3. difficulty-bucket profile data shows a different endpoint has stronger hard-task quality

The live request details also show that some controller responses emit `preferredEndpointIds` covering the full candidate pool, which adds a ranking bonus without actually narrowing the endpoint set.

## Reproduction Verification

Reproduced through live request detail inspection on the rebuilt runtime at `http://127.0.0.1:3461`:

1. quality-oriented controller requests still route from generic latest profiles because `difficultyRouting` is absent in controller-only mode
2. controller directives that list every allowed endpoint still flow into `routingModelRank` preference bonuses

## Data Flow Trace

### Root Cause A: controller-only quality requests never infer an observed difficulty bucket

`executeBridgePlan()` currently calls `readObservedProfilesForRouting()` with:

- `difficultyBucket = plan.routingDiagnostics?.difficultyRouting?.difficulty`

That means difficulty-aware profile overrides are only used when the earlier difficulty classifier already produced a bucket.

For `controller.remote-only` quality requests:

1. `maybeApplyDifficultyRouting()` does not run
2. `maybeApplyControllerRouting()` can still switch the final strategy to `quality`
3. `executeBridgePlan()` still passes `undefined` as `difficultyBucket`
4. `readObservedProfilesForRouting()` falls back to endpoint-wide latest profiles

So controller-selected quality routing does not consume the hard-task benchmark/profile slice that the runtime already stores.

### Root Cause B: full-pool controller endpoint rankings create artificial preference bias

`collectPreferredEndpointIds()` currently preserves any preferred endpoint list that is a filtered subset of `allowEndpoints`, including the case where the list equals the full allowed pool.

That allows controller guidance like:

- `[flash, pro, kimi, openai]`

to create `routingModelRank` bonuses inside the core router even though the guidance did not actually narrow the pool. This introduces deterministic score bias from rank ordering alone.

## Pattern Analysis

The runtime already has the right primitives:

1. bucketed observed profiles by `easy|medium|hard`
2. controller strategy directives normalized to `cost|balanced|quality`
3. alias execution modes that distinguish difficulty-driven and controller-driven routing

The remaining gap is the bridge between those primitives:

1. controller strategy does not currently infer a profile bucket when difficulty classification is absent
2. controller preferred endpoints are treated as meaningful even when they are only a reordered copy of the full candidate pool

## Root Cause Summary

1. controller-mode quality routing still reads generic latest observed profiles because the bridge only passes a difficulty bucket when `difficultyRouting` exists
2. controller `preferredEndpointIds` are too permissive because a full-pool list still turns into `routingModelRank` preference bias

## Fix Strategy

1. add RED regressions proving:
   - controller-mode quality routing should use hard-bucket observed profiles when difficulty routing is absent
   - full-pool `preferredEndpointIds` should collapse to no endpoint ranking override
2. patch the bridge to infer an observed difficulty bucket from controller strategy when appropriate
3. tighten controller preferred-endpoint handling so only strict subsets of the allowed pool produce routing-model rank guidance
4. rebuild and re-run live controller alias probes to confirm harder requests stop collapsing onto the generic freshest endpoint
