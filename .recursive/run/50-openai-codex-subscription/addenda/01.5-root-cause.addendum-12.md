Scope note: This addendum covers the remaining package-level host test failures that appeared after the canonical alias-matrix and controller-timeout changes.

## Error Analysis

Package-level `corepack pnpm --filter @role-model-router/runtime-host-bridge test` currently fails in three places:

1. `test/executable.test.ts`
   - fails during import-time SEA bundling with esbuild resolution errors for many workspace runtime packages
2. `test/routable-inventory-bootstrap.test.ts`
   - stale expectations still assume broad inventory fallback for aliases with stale model hints
3. `test/validate-vendors.test.ts`
   - the end-to-end mock vendor validation now exceeds the old `15000` ms per-test timeout

## Reproduction Verification

Reproduced with:

- `corepack pnpm --filter @role-model-router/runtime-host-bridge test`

Observed failure classes:

1. executable suite import crash
2. two stale alias bootstrap assertion mismatches
3. one test timeout

## Data Flow Trace

### Root Cause A: `package-sea.ts` executes packaging on import

`/role-model-router/apps/runtime-host-bridge/src/package-sea.ts` ends with:

- `if (import.meta.url === pathToFileURL(__filename).href) { ... }`

That condition is always true for the module itself because `__filename` is derived from
`import.meta.url`. So importing the module from `test/executable.test.ts` immediately runs
`packageSeaRuntime()`, which invokes esbuild and the SEA prep flow during test module load.

That is why the executable test fails with bundling errors instead of only asserting metadata.

### Root Cause B: routable inventory bootstrap tests still expect broad alias widening

The canonical alias-matrix and strict alias-resolution patch intentionally changed alias behavior:

1. aliases now resolve only through `alias.modelIds`
2. invalid or stale model ids no longer widen to the whole inventory
3. stale-only aliases are omitted from model-list output because they resolve to zero endpoints

`test/routable-inventory-bootstrap.test.ts` still expects:

1. a mixed alias with one stale local hint to widen back to the local endpoint
2. a fully stale alias to remain present in `/v1/models`

Those expectations are now wrong.

### Root Cause C: vendor validation timeout is stale relative to current routing work

`test/validate-vendors.test.ts` still caps the large mock end-to-end vendor validation at
`15000` ms.

That validation now includes more sequential runtime boots and intelligent alias paths than
the old budget reliably allows, especially after the controller path was made more realistic.

The runtime behavior is not hanging; the test budget is simply too short for the current
validation workload.

## Root Cause Summary

1. `package-sea.ts` uses an invalid main-module check and therefore runs SEA packaging during import.
2. routable inventory bootstrap assertions were not updated to the new strict alias semantics.
3. the vendor validation test timeout is lower than the real execution time of the current end-to-end validation.

## Fix Strategy

1. replace the `package-sea.ts` direct-execution guard with a real process-entry-based check and add an explicit regression assertion
2. update `test/routable-inventory-bootstrap.test.ts` to assert the strict alias behavior now implemented
3. increase the vendor validation test timeout to a value consistent with the current validation workload
4. rerun the package-level host suite
5. run a separate alias-verification pass against the live runtime and inspect actual routing decisions
