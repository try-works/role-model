Scope note: This addendum records the restart-time remote-health false negative discovered after the routing-alias repair. The runtime was marking healthy remote endpoints degraded because the probe compared canonical runtime model ids against raw provider `/models` ids with exact string equality.

## Root Cause Summary

Observed live behavior before the fix:
- after runtime restart, DeepSeek, Moonshot, and only GPT 5.4 differed in health state
- `/healthz` showed the `remote-health` stage degrading on `model-not-found`
- DeepSeek requests had already succeeded live, proving execution could work even while bootstrap classified the endpoint as degraded

Confirmed failure boundary:
1. `/role-model-router/apps/runtime-host-bridge/src/remote-health-probe.ts` fetched provider `/v1/models`
2. it extracted `data[].id`
3. it compared those ids with exact equality against canonical runtime ids such as `deepseek/deepseek-v4-flash`
4. `provider-openai` request execution strips the provider prefix before sending the request body model field, so runtime execution and health probing were using different comparison rules
5. live DeepSeek `/v1/models` returned `deepseek-v4-flash` and `deepseek-v4-pro`, not the prefixed runtime ids

Live evidence after inspection:
- DeepSeek `/v1/models` returned unprefixed ids and should have been treated as healthy for canonical ids `deepseek/deepseek-v4-flash` and `deepseek/deepseek-v4-pro`
- Moonshot `/models` returned only `kimi-for-coding`
- the current Moonshot account is configured for `moonshot/kimi-k2.7-code`, so its remaining degraded state after the fix reflects a distinct provider/model-contract mismatch rather than the DeepSeek false-negative bug

## Fix Boundary

The bounded correction is to normalize comparable model ids in the remote-health probe using the same prefixed/unprefixed equivalence that live OpenAI-compatible request execution already relies on. This repair is intentionally narrow:
- fix false degraded emission for canonical ids whose provider `/models` payload omits the provider prefix
- keep genuine `model-not-found` degradation when no comparable id exists
- preserve existing bootstrap receipts and routable-inventory gating
