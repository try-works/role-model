## Error Analysis

Observed operator behavior:

- `/app/router/strategy` can persist `Strategy B - Intelligent` and `Hybrid`
- `/app/router` then shows:
  - `Strategy: controller`
  - `Execution mode: hybrid`
  - `Alias pools: 0`
  - `No model aliases are configured yet.`

This is internally inconsistent because the routing posture is configured, but the corresponding alias surface that the router overview and downstream OpenAI-compatible runtime use as their model-pool abstraction is absent.

## Reproduction Verification

Static reproduction path from current code:

1. `runtime-ui` saves only `routingStrategy` and `executionMode` through `updateRuntimeConfig(...)`.
2. `mergeUnifiedRuntimeConfigDocuments(...)` in `/role-model-router/apps/runtime-host-bridge/src/unified-runtime-config.ts` merges and parses that patch.
3. `canonicalizeUnifiedRuntimeRoutingAliases(...)` only renames the primary alias when `config.modelAliases.length === 1`, and the previous logic skipped the `routingStrategy: null` (`Use runtime default`) case entirely.
4. If the config starts with no `model_aliases`, no alias is synthesized.
5. If the config starts with one alias and execution mode later changes, the alias id can be renamed while the alias pool remains stale for the new mode.
6. `readRouterSummaryData()` in `/role-model-router/apps/runtime-host-bridge/src/index.ts` builds `aliasInventory` only from `currentUnifiedRuntimeConfig?.modelAliases ?? []`.
7. `/role-model-router/apps/runtime-ui/app/routes/router.tsx` shows `Alias pools: 0` and the empty-state message because both runtime-config aliases and router-summary aliases are empty.

Reproducible: `Yes`
Deterministic: `Yes`

## Data Flow Trace

1. Operator saves routing posture.
2. Backend persists strategy and execution mode.
3. Backend does not materialize a primary alias matrix entry when none exists, and it does not refresh single-alias pools for every routing/execution-mode combination.
4. Router summary reports no alias inventory or stale alias hints.
5. Router overview renders the routing posture but cannot expose the correct alias pool.
6. Downstream consumers that prefer `modelAliases[0]` also lose the expected canonical alias.

## Root Cause Summary

Root cause:

- the config canonicalization path handled **alias renaming** but not full **alias materialization**
- the runtime apply path did not maintain a routing-strategy/execution-mode alias matrix for zero-alias or single-alias configs
- the router summary path treats persisted aliases as the sole source of truth and does not synthesize a fallback alias from the effective routable inventory

Why the bug exists:

- `/role-model-router/apps/runtime-host-bridge/src/unified-runtime-config.ts` assumed a primary alias already exists when routing strategy changes and treated `routingStrategy: null` as outside canonical alias naming
- `/role-model-router/apps/runtime-host-bridge/src/index.ts` computed alias inventory strictly from persisted `modelAliases` and did not rematerialize the primary alias pool on startup/apply
- `/role-model-router/apps/runtime-ui/app/routes/router.tsx` is only reflecting the backend truth, so the UI is not the root cause

Failure boundary:

- any runtime config variant that has zero or one primary alias while routing strategy and execution mode change, including `Use runtime default`

## Fix Strategy

The fix must satisfy all of these together:

1. backend startup and update/config-application paths must materialize a canonical primary alias matrix for zero-alias and single-alias routing configs
2. the alias id must match the current routing strategy plus execution mode naming contract, including `Use runtime default` and custom strategy strings
3. the materialized alias model pool must resolve against the effective routable inventory for the selected execution mode
4. regression coverage must prove this across routing-strategy families and all execution modes, not only the reported `controller + hybrid` case
5. rebuilt-runtime browser verification must confirm the alias appears in `/app/router` for persisted routing posture without requiring a manual repair save
