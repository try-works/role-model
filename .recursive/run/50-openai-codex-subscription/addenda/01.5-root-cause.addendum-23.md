## Root Cause

After addendum `22`, live exact-model web-search verification improved but did not fully converge:

1. OpenAI GPT-5.4 completed normally.
2. Kimi K2.7 Code completed after the bridged continuation loop.
3. DeepSeek V4 Flash completed after the bridged continuation loop.
4. DeepSeek V4 Pro still returned `status: completed`, but its assistant text body contained
   DSML tool-call markup like:
   - `<｜｜DSML｜｜tool_calls>`
   - `<｜｜DSML｜｜invoke name="web_search"> ...`

That means the remaining bridge gap is not missing tool execution or missing loop control.
The remaining gap is that DeepSeek can surface a tool request in provider-specific textual DSML
markup rather than in the normalized OpenAI `tool_calls` field.

The current bridge only auto-continues when `normalized.toolCalls.length > 0`.
So when DeepSeek V4 Pro encodes a follow-up tool request in DSML text instead, the bridge treats
the turn as final assistant output and stops too early.
