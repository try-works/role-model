## Root Cause

Live repro against `3462` showed that a non-controller request with
`x-role-model-requested-role-id: coder.review` could fail with:

`{"error":"Chosen endpoint  is not present in the registry result."}`

The failure chain is:

1. chat and responses requests start as `taskType: "text.chat"`
2. `applyRequestedRoleExecutionPolicy(...)` only retargets the task when:
   - the current task already belongs to the requested role, or
   - the role supports exactly one task
3. `coder.review` supports both `code.edit` and `json.schema_adherence`, so the bridge kept the
   incompatible `text.chat`
4. router-core then enforced `allowed_roles` for `text.chat`, rejected `coder.review` with
   `ROLE_NOT_ALLOWED` on every candidate, and returned no chosen endpoint
5. adapter-execution surfaced that empty decision as the blank chosen-endpoint 400

So the bug is not in header transport or router-core role enforcement. The bug is the bridge-side
task coercion gap for explicit multi-task roles on non-controller traffic.
