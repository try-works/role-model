Scope note: This addendum expands the Codex Subscription root-cause analysis from a GPT-5.4-specific capability bug to a provider-wide OpenAI subscription inventory and capability-matrix defect.

## External Capability Verification

Official OpenAI docs now establish the relevant `5.3+` model family boundary for this run:

- `gpt-5.5` is the latest flagship GPT-5 model.
- `gpt-5.4`, `gpt-5.4-mini`, and `gpt-5.4-nano` are current supported GPT-5.4 variants.
- `gpt-5.5-pro` and `gpt-5.4-pro` are current pro variants.
- `gpt-5.3-codex` remains a current Codex-oriented model.
- `gpt-5.3-chat-latest` is documented as deprecated.
- GPT-5.4 and GPT-5.5 family model docs list web search support in the Responses API, so web-search exclusion is not a valid model-level assumption for the supported family.

Therefore the operator contract for `Codex Subscription` must no longer be anchored to a GPT-5.4-only happy path, and it must not keep exposing pre-5.3 legacy entries as if they were current supported defaults.

## Runtime Failure Shape

The current runtime-host bridge still treats Codex Subscription model support as a flat hardcoded array:

- `/role-model-router/apps/runtime-host-bridge/src/index.ts`
  - `OPENAI_CODEX_SUBSCRIPTION_MODEL_IDS`

Current problems in that array:

1. it still includes `5.1` and `5.2` family entries that are outside the user-approved scope for this run
2. it omits current `5.4` and `5.5` variants such as:
   - `chatgpt/gpt-5.4-mini`
   - `chatgpt/gpt-5.4-nano`
   - `chatgpt/gpt-5.5`
   - `chatgpt/gpt-5.5-pro`
3. it mixes current, deprecated, and legacy model ids without any explicit lifecycle or capability encoding
4. it provides no maintained capability matrix that downstream tests can validate

Separately, several runtime validation seams remain hardcoded around `gpt-5.4` alias ids and recommended-model assumptions:

- `/role-model-router/apps/runtime-host-bridge/src/validate-vendors.ts`
  - uses `gpt-5.4`, `gpt-5.4-difficulty`, and `gpt-5.4-intelligent` as baked-in validation aliases
- `/role-model-router/apps/runtime-host-bridge/test/`
  - many tests assert `gpt-5.4` as the singular canonical OpenAI subscription alias or recommendation

That means the repo currently proves one narrow OpenAI path, not the provider-wide `5.3+` matrix the user requested.

## Root Cause Summary

**Root Cause:** Codex Subscription support is implemented as an outdated GPT-5.4-centric allowlist plus scattered `gpt-5.4` assumptions, rather than as a maintained OpenAI `5.3+` model matrix with explicit lifecycle and capability expectations.

**Location:** Primarily `/role-model-router/apps/runtime-host-bridge/src/index.ts` and `/role-model-router/apps/runtime-host-bridge/src/validate-vendors.ts`, with broad test coupling in `/role-model-router/apps/runtime-host-bridge/test/`.

**Detailed Explanation:** The earlier bridge-parity fix restored tool and web-search capability for one routed GPT-5.4 execution path, but the surrounding provider contract still lags the current OpenAI model catalog. Because the runtime only carries a flat list of subscription models, it cannot truthfully answer:
- which `5.3+` models are supported
- which models are deprecated but still tolerated
- which capabilities each supported model should expose
- which automated tests must pass for each model or variant

Without that matrix, support remains accidental and regressions will recur whenever model ids or aliases change.

## Fix Strategy

Replace the flat Codex Subscription allowlist with a maintained OpenAI subscription model manifest that:

- includes only `5.3+` family entries for this run
- captures lifecycle status for each entry
- captures the capability expectations we rely on in role-model
- derives the Codex Subscription model picker from that manifest
- drives the OpenAI-specific automated verification matrix from the same source

## Test Requirement

This scope extension requires RED/GREEN coverage that proves:

- only supported OpenAI `5.3+` models are exposed for Codex Subscription
- current supported variants like `gpt-5.4-mini`, `gpt-5.4-nano`, `gpt-5.5`, and `gpt-5.5-pro` are included
- deprecated entries such as `gpt-5.3-chat-latest` are marked truthfully if kept in the matrix
- provider synthesis, account activation, endpoint inventory, and request routing all remain correct for the supported matrix
- capability expectations do not regress silently for any supported model row
