Scope note: This addendum covers the remaining regression-risk gap after the controller allowlist and role-first UI fixes landed: the behaviors are validated by unit and route-source tests, but not yet locked down by end-to-end regression coverage at the real HTTP and rendered-route boundaries.

## Confirmed Working Behaviors

The previous slice established two important behaviors:

1. controller guidance is bounded to runtime-known roles, tasks, capabilities, strategies, and endpoint ids
2. the runtime Roles page now presents a role-first hierarchy and reveals task detail only on demand

Those behaviors are currently working in code and have targeted test coverage.

## Remaining Regression Gap

The current tests are still too close to the implementation seams:

1. controller contract tests focus on the helper directly
2. UI hierarchy tests focus on the role-task component directly
3. route taxonomy tests confirm static copy and source-shape expectations

What is missing is regression coverage that proves these behaviors survive at the operator-facing boundaries:

1. a live bridge HTTP request that exercises controller-guided routing and exposes sanitized controller diagnostics
2. a route-level render that proves the Roles page keeps tasks hidden by default and only reveals them after drill-down

## Concrete Root Cause

**Root Cause:** the run-50 fixes are only partially covered at the end-to-end boundary. The repo has strong unit and source regression tests, but it does not yet lock the newly confirmed controller and role/task behaviors behind integrated request-path and route-level regression checks.

## Why This Matters

Without end-to-end regressions:

1. a future refactor could preserve helper-unit tests while breaking the actual bridge request path
2. a future route refactor could preserve a pure component test while re-flattening the live role page hierarchy
3. operator-visible regressions would be rediscovered manually instead of being caught by CI

## Fix Strategy

1. add a host-bridge HTTP-level regression that sends a real `/v1/chat/completions` request through an intelligent alias and asserts the live routing diagnostics expose only accepted controller directives
2. add a host-bridge HTTP-level regression that proves the live role-policy endpoints expose the same role/task relationship consumed by the controller contract
3. add a runtime-ui route-level regression that verifies `/app/models/roles` preserves role-first copy and the task-detail affordance
4. keep the new tests focused on behaviors already confirmed to be working so this slice increases regression confidence without reopening implementation scope

## Test Requirement

This slice requires:

- RED tests that fail if the live host bridge stops exposing sanitized controller-routing diagnostics for intelligent alias requests
- RED tests that fail if live role/task API responses drift away from the controller-visible role/task relationship
- RED tests that fail if the roles route stops presenting role-first navigation language and task-detail drill-down language
- targeted package test runs demonstrating the new regression coverage passes
