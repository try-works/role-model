## Error Analysis

This run does not begin from a crash. It begins from a deterministic user-visible semantic failure: repeated GPT-5.4 traffic can take the native Codex Subscription path and still surface as permanently uncached to downstream OpenAI-compatible consumers and the Pi runtime CLI.

Observed failure family summary:

- Provider truth failure:
  - `provider-openai` still reports prompt caching unsupported and zeroes cache counters in normalization.
- Native Codex bridge serialization failure:
  - native Codex request shaping can forward `prompt_cache_key`, but transcript normalization and synthetic downstream response builders do not carry cache-detail facts back out.
- Ingress parity failure:
  - Responses ingress reads `prompt_cache_key`; Chat Completions ingress does not.
- Continuity-model failure:
  - routing has only endpoint continuity plus context-window-fit `cacheAffinity`; it has no cache-domain ledger or restore/create state.
- Telemetry truth failure:
  - canonical cache analytics depend on support flags derived from the current false capability matrix, so Codex rows can be excluded or labeled unavailable.
- Regression-proof failure:
  - the current automated suite does not encode the full matrix required to keep this regression from returning, and the repo has no rebuilt-runtime Pi CLI proof yet.

**Key Insight:** the user-visible `0%` symptom is not owned by Pi alone and not owned by one serializer alone. The current failure is cross-cutting: the OpenAI-family provider contract, the native Codex synthetic bridge contract, continuity state, and telemetry support truth all under-specify or discard cache facts.

## Data Flow Trace

### Trace 1: False unsupported / false-zero provider normalization

1. `getOpenAICapabilities()` hardcodes `promptCaching.supported: false`, `mode: "unsupported"`, `cacheReadTokens: false`, and `cacheWriteTokens: false` (`/role-model-router/packages/provider-openai/src/index.ts:22-42`).
2. Both normalization branches initialize `promptCache.used` false and all cache token counts to `0` (`/role-model-router/packages/provider-openai/src/index.ts:848-883`, `947-982`).
3. Vendor metadata can only be appended later, which means the baseline contract is already wrong.

**Trace 1 Root Cause:** the generic OpenAI-family provider layer still encodes a pre-cache-parity assumption for this runtime.

### Trace 2: Native Codex cache facts disappear between upstream and downstream

1. Native Codex request construction forwards `prompt_cache_key` when present (`/role-model-router/apps/runtime-host-bridge/src/index.ts:10360-10361`).
2. `normalizeCodexResponsesTranscript()` records `inputTokens` and `outputTokens`, but not cache-detail facts (`/role-model-router/apps/runtime-host-bridge/src/index.ts:9566-9775`).
3. Synthetic downstream Chat Completions and Responses builders emit totals only (`/role-model-router/apps/runtime-host-bridge/src/index.ts:9775-10086`, `11451-11526`).

**Trace 2 Root Cause:** the native Codex bridge owns the request and the downstream response surface, but the middle transcript/result contract is too thin to preserve cache truth.

### Trace 3: Request-hint parity and continuity restoration are incomplete

1. Responses ingress reads `prompt_cache_key` and `previous_response_id` (`/role-model-router/apps/runtime-host-bridge/src/index.ts:510-524`, `7944-7958`).
2. Chat Completions ingress forwards session affinity and reasoning, but not prompt cache (`/role-model-router/apps/runtime-host-bridge/src/index.ts:7781-7791`).
3. Routing currently treats `cacheAffinity` as only a token-fit check, not a persisted per-domain continuity record (`/role-model-router/packages/protocol-routing/src/index.ts:150-152`).

**Trace 3 Root Cause:** the runtime has no explicit cache-domain continuity model, so request hints and warmed-domain restore state cannot survive reroute sequences truthfully.

### Trace 4: Canonical telemetry surfaces are present but underfed

1. Runtime observability persists adapter prompt-caching support plus normalized read/write counts (`/role-model-router/packages/runtime-observability/src/index.ts:1044-1053`).
2. SQLite persistence stores those support booleans and counts directly (`/role-model-router/packages/sqlite-memory/src/index.ts:2667-2673`).
3. Analytics exclude unsupported rows for cache-hit-token-rate (`/role-model-router/apps/runtime-host-bridge/src/index.ts:16397-16412`).
4. Runtime UI returns `Caching unavailable` when support is false (`/role-model-router/apps/runtime-ui/app/lib/view-models.ts:682-689`).

**Trace 4 Root Cause:** canonical analytics and UI are structurally correct, but they consume false support truth from upstream layers.

## Root Cause Summary

**Root Cause:** cache truth is lost or misclassified at four ownership boundaries: the generic OpenAI-family provider capability/normalization layer, the native Codex transcript/result/response layer, the continuity model, and the telemetry-support truth layer.
**Location:** `/role-model-router/packages/provider-openai/src/index.ts`, `/role-model-router/apps/runtime-host-bridge/src/index.ts`, `/role-model-router/packages/protocol-routing/src/index.ts`, `/role-model-router/packages/runtime-observability/src/index.ts`, `/role-model-router/packages/sqlite-memory/src/index.ts`
**Detailed Explanation:** the repo already has downstream cache consumers and a working LiteLLM baseline, but the generic OpenAI-family provider still treats cache as unsupported, the native Codex bridge still strips cache-detail facts when converting raw transcript events into downstream OpenAI-compatible responses, the router has no persisted per-domain cache-affinity ledger, and canonical telemetry support flags inherit false capability truth from the provider layer. The result is a user-visible permanent `0%` or unavailable-cache posture on a path that should instead surface supported-zero or hit-state semantics truthfully.
**Fix Strategy:** Phase 2 must plan work in this order:
1. repair provider-openai capability truth and normalization
2. repair native Codex transcript/result/response cache-fact preservation
3. repair request-hint parity and continuity-ledger ownership
4. extend telemetry-support truth and downstream cache-surface proofs
5. add RED-first regression tests before implementation and reserve rebuilt-runtime Pi CLI proof for Phase 5
