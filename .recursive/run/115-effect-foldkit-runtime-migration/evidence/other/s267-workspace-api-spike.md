## RuntimeConfigEditor leaf contract (pilot)

Current code is app-level branches, not a leaf: `src/model.ts:17`, `src/message.ts:102-107`, `src/update.ts:406-443`, `src/view.ts:719-736`, `src/commands.ts:285-305`, `src/runtime-config.ts:57-70`. Observed gaps vs addendum 02: stale conflict is a generic `error`, not a conflict state; a refresh/Load replaces a dirty draft; no explicit reload-baseline action; no token test for late results.

Model (`Schema.Struct`): `status` = `not-loaded|loading|editing|confirming|invalid|pending|saved|conflict|error`; `baseline { text, configJson }`; `draft { text, configJson: Option }`; `diff: string[]`; `message`/`notice` optional; `token: number`. Ephemeral leaf state, so no persisted-model migration; keep the parent field name `runtimeConfigEditor`.

Messages (local union): `RequestedLoad`, `ChangedText {text}`, `RequestedReview`, `RequestedConfirm {token}`, `SucceededLoad {recordJson,token}`, `FailedLoad {message,token}`, `SucceededSave {recordJson,status,token}`, `FailedSave {message,status,reason,token}`, `RequestedReloadBaseline`, `RequestedDiscardDraft`.

OutMessages (facts to parent): `ChangedDraft {dirty}`, `Saved {applied}`, `Conflicted {}`. Parent keeps route/refresh/auth/canonical readback facts; child owns editor state only.

ViewInputs: `{ canWrite: boolean }` (token presence/auth is parent fact). Slot callbacks for shared chrome only, top-level.

HTTP service: `RuntimeConfigHttp` with `read: Effect<{body,status},RequestError>` and `save(config): Effect<{body,status},RequestError>`. Exact wire preserved from `runtime-config.ts`: GET/PUT `/api/role-model/runtime/config`; read `cache:"no-store"`, `accept:application/json`; save `content-type:application/json`, method PUT, body exactly `JSON.stringify(parsedConfig)`; `authorization: Bearer <token>` only when token configured; status passthrough (400 must not look like success). One application-lifetime client with optional `AbortSignal`, closed at shell shutdown. Preview: `Context.Service` + `Layer` merged into `EffectsLayer`; stable: current injected `createRuntimeConfigClient` (already one per `createShellApp`).

Save semantics to preserve and tighten: parse -> review with top-level diff -> confirm (token, pending fences double submit) -> pre-save GET compare pretty text against `baseline.text`; mismatch = `conflict`, draft retained, **no PUT**, message "Server config changed since Load; review the new snapshot before saving.". `RequestedReloadBaseline` is the only path that replaces baseline+draft with server text. PUT 409 = `conflict` (not generic error); other non-2xx/network = `error`; both retain draft and allow retry. Success = re-read, replace baseline+draft with server text, notice "Applied snapshot from server". All async results fenced by exact `token`; a newer load makes older results no-ops.

## Behavioral RED/GREEN (exit criteria for the pilot)

RED must fail for the missing behavior, not a missing import: (1) pre-save GET changed -> `status=conflict`, draft text unchanged, zero PUT, exact message; (2) explicit `RequestedReloadBaseline` replaces baseline+draft only on request; a passive refresh cannot overwrite a dirty draft; (3) late `SucceededSave` with `token-1` is ignored and confirm while `pending` emits zero commands; (4) 500/network failure retains draft and a retry emits exactly one PUT with the same body and a new token; (5) wire order GET/PUT/GET, method/path/headers/`cache`/body exact, bearer only with token, read 400 status preserved, one client instance; (6) OutMessage `ChangedDraft`/`Saved`/`Conflicted` emissions; (7) scene states: not-loaded only Load, invalid/error alert, confirming diff, pending disabled, saved notice (port s256 cases). GREEN = the same suite passes via `pnpm --filter @role-model-router/runtime-ui-next test` (tsc + vitest + node tests), then the preview gate below. No pass is claimed now.
