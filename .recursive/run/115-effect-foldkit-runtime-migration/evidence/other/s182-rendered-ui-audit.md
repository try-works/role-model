# S182 A rendered-UI audit that runs offline, and the fifth visual defect it foundFour rounds of finding render-only defects by hand ended in the obvious conclusion: it should be a script. Chrome is installed here and Node 24 ships a global `WebSocket`, so this needs **no new dependency**.## `scripts/runtime/audit-rendered-ui.mjs`Drives headless Chrome over the DevTools protocol and checks, per route:| Check | The defect it represents ||---|---|| crash banner text | my S181 regression (`Application Crash`) || page text length | blank / unrendered route || invisible controls (`colour == background`) | S175 Studio "Run" || unnamed controls, or a name longer than 60 chars / containing a newline | S177 filter selects || contrast below 4.5:1 per text element | S178 light theme 1.12:1 || horizontal overflow, with the offending elements named | **found this round** || viewport emulation (`--width/--height`) | responsive behaviour I could not test before |Usage: `node scripts/runtime/audit-rendered-ui.mjs --url http://127.0.0.1:6201` (or `--exe … --static-root … --fixture-root …` to spawn its own host). Exit 0 clean, 1 failures, **2 not run** when no browser is present. Also wired as `pnpm run runtime:audit-rendered-ui`.## The defect it immediately found```FAIL / - horizontal overflow at 1265px: MAIN.rm3-next-shell ml-3 w-full max, …FAIL / - horizontal overflow at 390px:  MAIN.rm3-next-shell ml-3 w-full max, …```The shell main column used `ml-3 w-full`: 100% of the row **plus** 12px of margin, so the page scrolled sideways at every width. Fixed to `ml-3 min-w-0 flex-1 max-w-[1138px]`.Why my earlier manual overflow check missed it: I asked `scrollWidth > clientWidth` **at 1920**, where the max-width cap absorbed the margin. The audit runs at 1280 by default and now also at 390, where nothing absorbs it.## Verified```20 routes x 1440x900  ->  0 failures20 routes x  390x844  ->  0 failures```Screenshot at 1920 unchanged (the cap hid the bug there), so the fix preserves the desktop layout.## Regression guard`test/s182-shell-overflow.test.mjs`: the main column must use `min-w-0 flex-1` and must **not** use `w-full`. RED 0/1 against committed source, GREEN 1/1 after; **9/9** across the five UI invariants.## What is still not gatedThe audit exists and passes, but it is **not in CI**. `build-binaries.yml` would need a browser on the runner and an advisory-to-blocking policy, exactly like the two R39 steps that are still advisory pending `vars.R39_VERIFY_BLOCKING`. That remains a decision I have recorded rather than taken.
