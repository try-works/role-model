## Findings

**F1 — Major, contract bug: repeated same-step reads are occurrence-paired, not multiset-matched.** `groupByStep` (compare.ts:200-211) preserves actual list order, and `compareRequestTraces` pairs expected occurrence *i* with actual occurrence *i* (compare.ts:319-331). Required semantics are an order-insensitive multiset. Minimal input:
`first = trace({step:"poll", query:[["page","1"]], body:"A"})`, `second = trace({step:"poll", query:[["page","2"]], body:"B"})`;
`compareRequestTraces([first,second,first],[second,first,first])` returns four findings (`query_mismatch`/`body_mismatch` at indices 0 and 1) instead of `[]`. With unequal counts it can also misattribute which same-step occurrence is extra. The header comment "multiset keyed by step" (line 16) describes the flaw. Correctness/contract bug, not style; confirmed by the new test and RED log.

**F2 — Major, false PASS: causal order ignores reads.** `findCausalOrderDifference` filters out every `kind === "read"` event (compare.ts:279-284), while read dependency strings are still compared (268-272). A dependent read, or the read authorizing a write, may move across its predecessor without a finding. Minimal:
- `initial=read`; `write=mutation dependency:"initial"`; `readback=read dependency:"write"`. `compare([initial,write,readback],[initial,readback,write])` → `[]`, though `readback` now precedes `write`; a `causal_order_mismatch` should be reported.
- `compare([initial,write],[write,initial])` → `[]`, though `write` depends on `initial`.

The controller's two new causal tests fail exactly here. Violates the task's explicit "causal reads"/preserve-order requirement; false PASS is the worse direction.

**F3 — Major, contract gap: dependency labels are opaque; no referential, acyclic, or root validation.** compare.ts:268-272 only requires non-null for mutation/tool/turn and string equality. Nothing resolves a dependency to an event, checks that it precedes, or rejects self/forward/cyclic references. Minimal: `compare([mutation step "a" dependency "a"], [same])` → `[]` (self-cycle passes); `dependency:"ghost"` on both sides → `[]` (missing parent passes); `a→b, b→a` passes. "Missing parent/selfcycle" is therefore unimplemented. The first-mutation root contract is also undefined: a first mutation with `dependency:null` reports `dependency_mismatch` even for identical captures, while the tool/turn test passes `dependency:"root-action"` although no such event exists, contrary to compare.ts:7-9 ("names the stable label of the causal predecessor"). Choose and enforce one policy — a required root sentinel, or null allowed only for a first mutation — and test it. Either implement graph validation (preferred per the task) or explicitly narrow the contract with owner sign-off; the silent middle is not acceptable.

**F4 — Test-coverage gap in the accepted 28.** The 28 tests never repeat a step label for reads: "ignores independent read order and keeps duplicate reads" and "reports a missing duplicate read" use `read-alpha`/`read-beta` (distinct steps), so they exercise neither multiplicity nor variants; the `s1a-tdd.json` coverage claim that duplicates are retained is unsupported. There are also no tests for causal-read ordering, dangling/self/cyclic dependencies, root handling, or same-step variants under missing/extra counts. That is why F1-F3 survived 28/28. The controller-added tests (test lines 24-43) cover three symptoms but fail, and still do not cover dangling/self-cycle/root.
