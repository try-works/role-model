## Error Analysis

The user reports two manifestations of the same defect:

**Manifestation 1:** `/app/models` freezes for ~1 minute after clicking "Save bindings" or "Eject from pool."
**Manifestation 2:** Navigating from `/app/models` to `/app/models/benchmark` takes ~1 minute.

The investigation traced both to a single root-cause chain: a synchronous, unindexed, full-table-scan SQLite query that parses large JSON blobs on the Node.js event loop.

## Reproduction Verification

**Manifestation 1 (Save bindings):**
1. Start packaged runtime on `http://127.0.0.1:3456`
2. Navigate to `/app/models`
3. Select a model with a backing provider account
4. Click "Save bindings"
5. Observe "Saving…" persists for ~60 seconds
6. Concurrent `curl http://127.0.0.1:3456/healthz` times out

**Manifestation 2 (Cross-route benchmark navigation):**
1. Navigate to `/app/models`
2. While the deferred `fetchRuntimeRequests()` is still in flight, navigate to `/app/models/benchmark`
3. Observe blank benchmark page for ~90 seconds
4. Concurrent `/healthz` times out after 90 seconds
5. After recovery, benchmark reads return in normal time (4.17s suite, 856ms candidates)

**Reproducible:** Yes, consistently on the live database (6.90 GB, 5,762 observation rows).
**Deterministic:** Yes — the slow behavior is directly proportional to database size and absence of indexes.

## Root Cause Summary

**Root Cause for both manifestations:**
The `listRecentRuntimeObservations()` SQLite query (1) selects the large `observation_json` column and parses it on every row, (2) has no index supporting its `ORDER BY created_at_ms DESC, request_id DESC` clause, causing a full table scan and temporary B-tree sort that blocks the Node.js event loop for up to 60 seconds on the 6.90 GB database. This single synchronous operation freezes all other server operations including `/healthz` and the benchmark route's startup endpoints.

**Primary location:** `role-model-router/packages/sqlite-memory/src/index.ts:4081-4118` (`listRecentRuntimeObservations`)

**Contributing locations:**
- `role-model-router/apps/runtime-ui/app/routes/control-models.tsx:578-587` (`refreshObservedRequestEvidence` — calls `fetchRuntimeRequests()` after every mutation)
- `role-model-router/apps/runtime-ui/app/routes/control-models.tsx:597-612` (`saveAccountRoles` — blocks on `refreshObservedRequestEvidence`)
- `role-model-router/apps/runtime-ui/app/routes/control-models.tsx:615-619` (`refreshModelState` — blocks on `refreshObservedRequestEvidence`)
- `role-model-router/apps/runtime-ui/app/routes/control-models.tsx:111-140` (`startDeferredConfiguredModelsBootstrap` — no `AbortSignal` on deferred fetch)
- `role-model-router/apps/runtime-ui/app/routes/control-benchmark.tsx:570-612` (single `Promise.all` with 7 reads, no essential/advisory split)

**Detailed Explanation:**

1. The `runtime_observations` table stores large observation blobs (multi-MB JSON in `observation_json`) for each request.
2. The table has a `client_request_id` column added at schema creation time, but `listRecentRuntimeObservations()` never selects it.
3. Instead, the function selects `observation_json`, calls `JSON.parse()` on every returned row, and extracts `clientRequestId` from the parsed blob.
4. The query's `ORDER BY created_at_ms DESC, request_id DESC` has no supporting index, so SQLite performs a full table scan over 6.90 GB and sorts in a temporary B-tree.
5. This synchronous work runs on Node.js's single event loop, blocking ALL other operations.
6. The UI mutation handlers await this call before clearing the "Saving…" / "Removing…" button state, making the freeze user-visible.
7. The Models route's deferred bootstrap opens this request without an `AbortSignal`, so when the user navigates to benchmark, the server-side work continues blocking the event loop, gating the benchmark route's startup `Promise.all`.

**Fix Strategy:**

The fix requires changes in three layers:

**Layer 1 — SQLite (sqlite-memory):**
- Add an idempotent migration creating index `idx_obs_created_at` on `(created_at_ms DESC, request_id DESC)`
- Rewrite `listRecentRuntimeObservations()` to select `client_request_id` directly (the column already exists) instead of parsing `observation_json`
- Keep the individual `observation_json` path only for single request-detail reads

**Layer 2 — UI mutation handlers (control-models.tsx):**
- Decouple `refreshObservedRequestEvidence()` from mutation completion
- Clear "Saving…" / "Removing…" after canonical mutation truth is confirmed
- Fire advisory reads independently without blocking the button state
- Pass `AbortSignal` to the deferred bootstrap fetch so navigation can cancel in-flight requests

**Layer 3 — Benchmark route (control-benchmark.tsx):**
- Split the 7-read `Promise.all` into essential (suite metadata, preferences, runtime summary) and advisory (full candidates, summaries, runs)
- Render the benchmark shell and essential controls as soon as the essential reads resolve
- Load advisory data progressively with truthful loading/error states

**Test Strategy:**
- SQLite: regression tests with large out-of-row blobs; EXPLAIN QUERY PLAN assertions
- UI mutations: browser regression holding `/api/role-model/requests` open indefinitely, proving both mutation actions complete
- Benchmark navigation: cross-route regression proving shell/controls render within 500ms while Models request history is blocked
