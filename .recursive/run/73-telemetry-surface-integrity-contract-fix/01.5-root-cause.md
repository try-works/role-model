## Error Analysis

The implementation addressed visible symptoms but did not place decisions at the layer that owns the required fact:

- cache-key synthesis runs before selected-target capability truth is available and has no canonical message fallback
- usage source exists transiently but the canonical event schema and persistence path discard it
- the UI infers provenance from numeric presence after backend truth has already been lost
- chart spacing uses fixed constants instead of deriving axis reserve from formatted data
- browser tests depend on ambient rows and an incorrect element selector instead of a deterministic fixture and geometry contract
- phase receipts claim verification that was neither ordered nor executed

**Key Insight:** these are ownership and contract failures, not isolated Kimi, request-detail, or individual-chart defects. Facts are being guessed downstream or fixed with constants because their canonical producing layer does not expose an extensible contract.

## Data Flow Trace

### Trace 1: prompt-cache request

1. A logical request carries an explicit key, a continuity id, or only system/messages.
2. Initial mapping synthesizes before final target capability selection.
3. Only continuity ids are supported; message-only requests remain unsynthesized.
4. Unsupported targets can receive a synthesized intent because capability truth was unavailable at the decision point.
5. The source field is not carried into canonical observability.

**Root cause:** cache synthesis combines continuity derivation and provider-wire activation too early. Continuity material must be derived independently, then activated only at the final capable target boundary with source persisted.

### Trace 2: usage and request-size truth

1. Provider response usage can occur top-level or under a final choice, including tool-calling final chunks.
2. The parser recognizes only part of the required matrix.
3. Missing usage is estimated from logical messages rather than the captured outbound wire body.
4. Adapter normalization temporarily attaches `source`, but canonical `UsageEvent` omits source and availability.
5. Persistence stores numbers only; request detail then guesses `measured` from numeric presence.
6. Unavailable and genuine zero can become indistinguishable to analytics.

**Root cause:** no canonical token-truth contract spans provider normalization, schema, persistence, API, analytics, and UI. Provenance and availability must be part of the persisted fact, not display metadata.

### Trace 3: shared chart geometry

1. Data values are formatted into tick labels.
2. All charts reserve fixed axis widths independent of those labels.
3. Legends use a fixed or mismatched inset and plot height bypasses the exported contract.
4. Wide left labels clip while unused right reserve makes the plot appear off-center.
5. Area/bar and ranking consumers lack complete contract regression coverage.

**Root cause:** geometry is constant-driven instead of data-driven. One deterministic resolver must derive bounded gutters/reserves from formatted labels and feed every shared time-series chart kind.

### Trace 4: regression and rebuilt-runtime evidence

1. The browser harness starts without deterministic populated telemetry.
2. Tests select an element type the component does not render and do not measure bounding boxes.
3. Request detail selects an ambient first row, permitting `n/a` to pass.
4. Source-level QA is treated as verification even though R9 requires a packaged implementation commit.

**Root cause:** the verification contract does not control data identity, selectors, geometry, or build provenance. Deterministic fixtures and implementation-commit package evidence are required.

## Root Cause Summary

**Root Cause:** the implementation lacks canonical, end-to-end contracts for capability-aware cache activation, token value/source/availability, data-dependent chart geometry, and deterministic rebuilt-runtime verification.

**Locations:** runtime-host request shaping; provider-openai usage extraction; adapter/protocol/observability/persistence contracts; runtime-ui shared chart and request-detail consumers; QA fixture and Playwright surfaces; recursive run receipts.

**Fix Strategy:** execute addendum SP1-SP8 in ownership order. Derive continuity safely, activate it at the negotiated capability boundary, persist token provenance with availability, derive chart geometry from formatted data, seed deterministic browser facts, and regenerate ordered phase evidence.

**Test Plan:** strict RED tests for every cache, usage, persistence, UI, chart, and browser invariant before replacement production edits; then package the implementation commit and verify it on a dedicated non-`3456` port.
