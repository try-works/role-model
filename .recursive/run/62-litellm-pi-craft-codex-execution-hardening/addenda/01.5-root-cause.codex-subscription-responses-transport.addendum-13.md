## Role-Model Current Behavior

Role-Model currently executes Codex Subscription through:

- `createSystemCodexExecutionAdapter()`
- `executeCodexAppServerTurnOverStdio()`
- `codex app-server -c cli_auth_credentials_store="file" --listen stdio://`

That path then converts a completed app-server turn into either:

- non-streaming Chat Completions JSON; or
- non-streaming Responses JSON.

This means downstream streaming is later synthesized after the turn is complete. Even if app-server emits internal deltas, Role-Model is not using the same provider-facing streaming contract that Pi uses.

## Corrected Root Cause

Root cause: Role-Model uses the wrong Codex Subscription execution transport for routed downstream model requests. It shells out to Codex app-server and adapts a completed agent turn, while Pi's provider implementation uses the ChatGPT Codex Responses transport directly and preserves Responses stream events.

The app-server collapse explains the visible symptom, but preserving app-server deltas is not the right durable fix. The right fix is a native Codex Subscription Responses execution adapter in Role-Model.

## Non-Root-Causes

- Streaming is still not a routing eligibility criterion.
- Reasoning/streaming absence must not make a routed endpoint ineligible by itself.
- This is not a Pi-specific or Craft-specific fix.
- This is not a reason to route Codex Subscription through LiteLLM.
- This is not a reason to classify `ai-sdk-openai`, LiteLLM, or Codex app-server as providers.

## Corrected Fix Boundary

Role-Model should implement a generic execution-normalization pattern:

1. Route to the selected endpoint.
2. Choose the selected endpoint's execution adapter.
3. For OpenAI Codex Subscription endpoints, execute via ChatGPT Codex Responses SSE using stored OAuth credentials.
4. Parse Responses events into a provider-neutral stream transcript:
   - text deltas
   - reasoning/thinking deltas
   - tool-call deltas where supported
   - usage and terminal status
5. Convert that transcript to the downstream request shape:
   - Chat Completions SSE for `/v1/chat/completions`
   - Responses SSE or Responses JSON for `/v1/responses`
6. Preserve exact-model and alias-routed behavior identically after routing.

## Provider, Vendor, Adapter Taxonomy

For Codex Subscription GPT:

- `providerId`: `openai`
- `providerFamily`: `openai`
- `executionPath`: `codex-subscription-responses`
- `upstreamSurface`: `chatgpt-codex-responses`
- `adapterFamily`: a Role-Model owned Codex Responses adapter, not `ai-sdk-openai`
- `vendorId`: should no longer be `codex-app-server` when the direct Responses transport is used

Existing telemetry that says `vendorId = codex-app-server` is evidence of the old app-server execution path, not the desired final state.
