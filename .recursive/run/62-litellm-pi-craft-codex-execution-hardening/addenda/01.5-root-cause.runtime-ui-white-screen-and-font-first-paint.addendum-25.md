## Issue

The packaged runtime can show a blank white document for an extended period before the React runtime UI appears, and the first painted text can appear to use fallback system typography rather than the design-system typeface.

## Evidence

- Live HTTP checks showed `/health` returns in ~267 ms and `/app` returns the app HTML in ~24 ms.
- Static CSS, JS, and bundled font assets are served successfully with correct content types.
- Headless Chromium and Microsoft Edge both rendered the live app quickly, but both emitted React Router's warning that the app provides no hydrate fallback while JS modules load.
- `root.test.tsx` explicitly forbids `HydrateFallback`, which preserves the blank-document behavior.
- `root.tsx` ships no font preload links, so first paint can use fallback fonts until CSS discovers and loads Inter.

## Root Cause

The packaged app removed the old boot screen but did not replace it with a minimal React Router hydration fallback. That leaves an empty body while JS modules load in slower browser/profile paths. Bundled fonts are self-hosted, but they are only discovered from CSS after the shell starts loading.

## Fix Strategy

- Add a minimal, non-boot-screen `HydrateFallback` that paints the design-system background and a restrained shell-loading message.
- Preload bundled Inter regular/semibold and IBM Plex Mono regular fonts in root links.
- Keep the old boot-screen strings absent.

## Verification Plan

- RED tests: root tests must require `HydrateFallback` and bundled font preload links.
- GREEN tests: root tests pass.
- Live verification: rebuild UI/package and trace the packaged app with Edge/Chromium to confirm no blank initial document, fast app visibility, no failed assets, and Inter applied.
