## Root Cause

The reproduced timeout was caused by Role-Model returning HTTP `503` for a deterministic pre-execution routing miss when the exact GPT endpoint was temporarily denied by execution cooldown. Pi treats `503` as retryable server unavailability, so a request that should fail quickly was retried until the Pi-side timeout. The runtime error body already said `no_eligible_target`; the incorrect part was the HTTP status classification.

The status was produced in `role-model-router/apps/runtime-host-bridge/src/index.ts` by `throwUnavailableExecutionTarget()`, which mapped any active cooldown to `503`. That is appropriate only when the server cannot serve generally. It is not appropriate for a deterministic model-specific routing result where all currently eligible endpoints for the requested model are denied by recorded cooldown receipts.
