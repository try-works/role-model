# Addendum 12 Root Cause: Routing-Agnostic Streaming

## Reproduction Evidence

The addendum 11 live request-detail evidence showed:

- DeepSeek through `difficulty.remote-only` emitted many reasoning/text deltas.
- Codex Subscription GPT through `chatgpt/gpt-5.4` returned successful content but only one downstream text delta.
- Craft alias-selected GPT also recorded only one downstream text delta.

The user correction clarified that the correct requirement is not "avoid GPT when thinking is requested." The correct requirement is that routed execution must preserve streaming generically across endpoints and providers.

## Data Flow Trace

Direct OpenAI-compatible HTTP path:

1. Provider returns SSE frames.
2. `readProviderStreamTranscript()` forwards chunks through `trackedStreamWriter`.
3. `provider-openai` parses the same raw transcript for normalized text/reasoning delta counts.
4. Downstream Pi/Craft receive incremental OpenAI-compatible Chat Completions chunks.

Codex Subscription app-server path:

1. Codex app-server emits JSONL messages such as `item/agentMessage/delta`.
2. `executeCodexAppServerTurnOverStdio()` appends those deltas into `outputText`.
3. `createSystemCodexExecutionAdapter()` converts the completed turn into a non-streaming Chat Completions body.
4. `createChatCompletionsStreamChunks()` later creates one synthetic downstream content chunk containing the full completed text.

Failure boundary: app-server deltas are collected but discarded as stream events before the response enters the generic OpenAI-compatible SSE writer.

## Root Cause

Root cause: the Codex Subscription app-server execution adapter collapses incremental app-server output into a completed response body, so routed streaming requests lose model/provider streaming granularity even though routing itself selected a valid endpoint.

Location:

- `role-model-router/apps/runtime-host-bridge/src/index.ts`
- `executeCodexAppServerTurnOverStdio()`
- `createSystemCodexExecutionAdapter()`
- replay path around `replayProviderStreamTranscript()`

## Important Non-Root-Causes

- Streaming capability is not a routing eligibility criterion and must not become one.
- Reasoning deltas are not guaranteed to be exposed by every execution path, but the runtime must preserve any reasoning/thinking deltas it receives.
- The bug is not specific to Pi or Craft. Pi and Craft expose the symptom because they are streaming downstream consumers.
- The bug is not fixed by classifying Codex Subscription GPT as ineligible for aliases.

## Fix Strategy

- Preserve app-server text deltas and reasoning/thinking deltas in a provider-neutral intermediate shape.
- When the original downstream Chat Completions request is streamed, convert those deltas into the same OpenAI-compatible SSE transcript used by direct provider paths.
- Let `replayProviderStreamTranscript()` forward that transcript through the ordinary downstream writer.
- Pass `reasoningRequested` through replay metadata so opted-in reasoning-only frames are not suppressed.
- Keep exact-model and alias paths identical after routing.
- Keep ordinary non-streaming responses unchanged.

## Test Strategy

- RED test: Codex/app-server reasoning or thinking deltas should normalize to `choices[].delta.reasoning_content` without exposing them as assistant-visible content.
- RED test: replaying a provider transcript should preserve leading reasoning-only chunks when reasoning was requested.
- GREEN verification: focused host-bridge tests, broad runtime tests, rebuilt runtime, real Pi CLI, real Craft runtime/client, raw SSE.
