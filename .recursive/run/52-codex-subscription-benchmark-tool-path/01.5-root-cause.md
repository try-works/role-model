## Root Cause Summary

**Root Cause:** The Codex Subscription benchmark tool path calls `createRuntimeToolRegistry` (which reads a testdata file excluded from production) instead of `createRequestScopedToolRegistry` (which builds an in-memory registry from request-scoped tools without file reads).
**Location:** `index.ts:12917`
**Detailed Explanation:** When a Codex Subscription benchmark case includes function tools, `buildCodexDynamicTools` extracts them from the request. The branch then calls `createRuntimeToolRegistry(options.repoRoot, currentRegistry, networkFetcher)` to create a tool registry. This function calls `loadMcpConnectorConfigs(repoRoot)` which reads `testdata/router-runtime/mcp-connectors.json`. On the packaged runtime, this file is excluded by `package-sea.ts:91` (`forbiddenProductionReleasePathFragments`), causing an `ENOENT` crash before the benchmark case can be evaluated. The `createRequestScopedToolRegistry` function already exists at line 5833 and creates an in-memory `ToolRegistry` from the same dynamic tools without any file reads, but is never called.
**Fix Strategy:** Replace `await createRuntimeToolRegistry(options.repoRoot, currentRegistry, networkFetcher)` with `createRequestScopedToolRegistry(codexDynamicTools)` at line 12917. Export `createRequestScopedToolRegistry` for direct unit testing. Keep `createRuntimeToolRegistry` for the non-Codex hosted-tools continuation path at line 13154.
