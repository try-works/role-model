## Root Cause Summary

Root Cause:

- `getQualityMetric(...)` evaluated measured quality before benchmark task, role, and group quality, so live measured profiles shadowed benchmark-taxonomy routing.

Location:

- `role-model-router/packages/core/src/router.ts`

Detailed Explanation:

- the addendum correctly enriched runtime candidates with assignment-aware benchmark evidence and added benchmark reason codes, but the router still returned from measured `judge_score` and `quality_score` first. Because rebuilt-runtime remote endpoints already had measured profiles, benchmark quality never became the active quality source during live routing.

Fix Strategy:

- add mixed-data regression tests first
- move benchmark quality evaluation ahead of measured quality in `getQualityMetric(...)`
- rerun focused tests and builds
- rerun rebuilt-runtime live probes for task, role, and group precedence
