## Hypothesis

**H1:** Replacing SERP dump with a forced text-only synthesize hop (tools without `web_search` / `tool_choice: none`) plus a structured non-SERP last-resort message will stop `[wordlim:` dumps.
**H2:** Raising batch continue budget and refusing duplicate queries will reduce exhaustion on multi-fact prompts.
**H3:** Stronger ticker-oriented tool/guidance text improves query quality but cannot guarantee ChatGPT index quality.

## Confirmed Root Cause

The adapter’s web_search fulfill loop, when the routed model keeps requesting search past `MAX_WEB_SEARCH_CONTINUES`, calls `finalizeSearchOnlyAnswer`, which presents raw ChatGPT SERP as the user-visible assistant answer. That aborts multi-phase Desktop tasks before local work. Secondary factors: soft “don’t search again” coercion and limited continue budget for multi-query turns.
