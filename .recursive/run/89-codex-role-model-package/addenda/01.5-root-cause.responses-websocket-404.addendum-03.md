## Error Analysis

**Error Message:** `unexpected status 404 Not Found: Not found, url: ws://127.0.0.1:3460/v1/responses`
**Stack Trace:** Codex Desktop WebSocket upgrade → adapter returns plain HTTP 404 body `Not found`
**File:Line:** `forwarder.ts` `startForwarder` had no `server.on("upgrade", …)`
**Key Insight:** Desktop signed-in mode still opens Responses WebSockets against the hijacked base URL; catalog `prefer_websockets: false` / managed `supports_websockets = false` do not stop Desktop from attempting WS and dying after 5 reconnects.

## Confirmed Root Cause

Adapter implemented Responses over HTTP/SSE only. Codex Desktop (signed-in / ChatGPT provider with `openai_base_url` → adapter) still initiates WebSocket mode to `/v1/responses`. Missing upgrade handling yields 404; Desktop treats that as fatal after reconnect budget.

## Hypothesis

Accept WebSocket upgrades on `/v1/responses`, bridge `response.create` frames into the existing HTTP forwarder (SSE events → WS JSON), and keep a connection-local `previous_response_id` cache so store=false continuation works.
