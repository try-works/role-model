## Error Analysis

This run does not begin from a crash. It begins from a deterministic semantic contract failure:

- native Codex streamed Chat Completions compatibility can emit tool calls, but non-stream Codex compatibility bodies can silently lose them
- provider-neutral continuation is replayed as chat-style messages even for native Responses targets
- request-side `parallel_tool_calls` intent can be lost or rewritten
- Codex benchmark subject turns still execute through Chat Completions instead of the newer Responses tool contract

Observed failure family summary:

- shared execution-contract failure:
  - `RuntimeExecutionRequest` does not model `parallel_tool_calls`
- Responses-ingress shape failure:
  - `body.input` is narrowed to plain messages and drops typed tool items
- native Codex non-stream parity failure:
  - non-stream transcript normalization does not preserve `function_call` items
- continuation-rendering failure:
  - bridge-managed follow-up turns are always encoded as assistant/tool chat messages
- benchmark-path failure:
  - benchmark subject turns remain chat-completions only
- regression-proof failure:
  - the current tests do not encode the full run-68 matrix

**Key Insight:** the defect is not “Codex tool calls are broken” in the abstract. The actual breakage is split across contract ownership boundaries: ingress parsing, the shared execution model, native Codex non-stream synthesis, Responses continuation rendering, and the benchmark subject surface.

## Data Flow Trace

### Trace 1: Missing request-side `parallel_tool_calls`

1. `RuntimeExecutionRequest` has no field for caller-controlled parallel tool policy (`/role-model-router/packages/adapter-execution/src/index.ts:95-108`).
2. Chat Completions ingress does not read `body.parallel_tool_calls` (`/role-model-router/apps/runtime-host-bridge/src/index.ts:8032-8052`).
3. Responses ingress does not read `body.parallel_tool_calls` (`/role-model-router/apps/runtime-host-bridge/src/index.ts:8196-8219`).
4. provider-openai therefore has nothing to forward generically, and the native Codex builder compensates by forcing `parallel_tool_calls: true` (`/role-model-router/apps/runtime-host-bridge/src/index.ts:10683-10688`).

**Trace 1 Root Cause:** the field is missing at the contract layer, so the current Codex request builder falls back to an adapter-owned hardcoded default.

### Trace 2: Native Codex non-stream loses function calls

1. Native Codex request execution returns an SSE transcript (`/role-model-router/apps/runtime-host-bridge/src/index.ts:10758-10777`).
2. Streamed Chat Completions compatibility uses `createCodexResponsesChatCompletionsStreamMapper()` and preserves `tool_calls` deltas (`/role-model-router/apps/runtime-host-bridge/src/index.ts:10206-10352`).
3. Non-stream handling instead calls `normalizeCodexResponsesTranscript()` (`/role-model-router/apps/runtime-host-bridge/src/index.ts:10777`).
4. That normalizer records only response id, text, reasoning, finish reason, and usage (`/role-model-router/apps/runtime-host-bridge/src/index.ts:9998-10111`).
5. Downstream non-stream bodies are then built from that tool-less transcript (`/role-model-router/apps/runtime-host-bridge/src/index.ts:10781-10799`).

**Trace 2 Root Cause:** the non-stream normalization contract is thinner than the stream-mapping contract and discards `function_call` items before downstream synthesis runs.

### Trace 3: Responses continuation is flattened into chat replay

1. Responses ingress narrows `body.input` to plain messages (`/role-model-router/apps/runtime-host-bridge/src/index.ts:6708-6731`, `8073-8074`).
2. Bridge-managed continuation builds a follow-up request by appending assistant `tool_calls` and `role:"tool"` messages (`/role-model-router/apps/runtime-host-bridge/src/index.ts:12361-12408`).
3. provider-openai then serializes those same messages into Responses `body.input` via `toOpenAIInput(...)` (`/role-model-router/packages/provider-openai/src/index.ts:56-75`, `801-840`).

**Trace 3 Root Cause:** the repo lacks a provider-neutral typed continuation history, so Responses-native targets never receive `function_call_output` replay.

### Trace 4: Benchmark subject turns stay on Chat Completions

1. `runCaseOnEndpoint()` stores `BenchmarkChatCompletionsExecutionResult` and executes turns through `executeBenchmarkTurn(...)` (`/role-model-router/apps/runtime-host-bridge/src/benchmark-runner.ts:331-395`).
2. Subject execution uses `deps.executeChatCompletions(...)` (`/role-model-router/apps/runtime-host-bridge/src/benchmark-runner.ts:315`, `612-614`, `1260`).
3. Existing benchmark tests stub only `executeChatCompletions(...)` and never exercise a Responses subject path (`/role-model-router/apps/runtime-host-bridge/test/benchmark-runner-judge.test.ts:300-353`, `510-585`).

**Trace 4 Root Cause:** benchmark execution still reflects the older Chat Completions subject contract and cannot directly verify Responses-native Codex tool behavior.

## Root Cause Summary

**Root Cause:** tool-call parity is currently under-specified at the contract level and inconsistently rendered across native Codex, bridge-managed continuation, and benchmark execution.
**Location:** `/role-model-router/packages/adapter-execution/src/index.ts`, `/role-model-router/apps/runtime-host-bridge/src/index.ts`, `/role-model-router/packages/provider-openai/src/index.ts`, `/role-model-router/apps/runtime-host-bridge/src/benchmark-runner.ts`
**Detailed Explanation:** the runtime evolved streamed tool-call handling and native Codex Responses transport without also promoting request-side `parallel_tool_calls`, typed Responses continuation history, and Responses-based benchmark subject execution into the shared execution model. As a result, the stream path is richer than the non-stream path, native Responses targets receive chat-style replay instead of typed replay, benchmark subject turns stay on the older surface, and the test floor does not enforce the missing cases.
**Fix Strategy:** Phase 2 must plan work in this order:
1. extend the shared execution and ingress contract for request-side `parallel_tool_calls`
2. repair native Codex non-stream transcript normalization and downstream synthesis for single and sibling tool calls
3. add a Responses-native continuation transformer for route switches to native Responses targets while preserving bridge-safe Chat Completions replay for bridge targets
4. migrate Codex tool-bearing benchmark subject execution to `/v1/responses`
5. add RED-first regression coverage before production edits and reserve rebuilt-runtime Pi CLI proof for Phase 5

## Root Causes

1. **RC1: the shared execution contract does not model request-side `parallel_tool_calls`**
   - Location: `/role-model-router/packages/adapter-execution/src/index.ts`
   - Why it matters: caller intent cannot survive ingress, routing, provider request building, or verification if the field does not exist in the shared contract.
2. **RC2: native Codex non-stream normalization is thinner than the streamed path**
   - Location: `/role-model-router/apps/runtime-host-bridge/src/index.ts`
   - Why it matters: non-stream `/v1/chat/completions` and `/v1/responses` bodies lose tool calls even though the stream path can preserve them.
3. **RC3: Responses continuation is not provider-neutral**
   - Location: `/role-model-router/apps/runtime-host-bridge/src/index.ts`, `/role-model-router/packages/provider-openai/src/index.ts`
   - Why it matters: route switches to native Responses targets cannot replay tool state as `function_call` plus `function_call_output` items.
4. **RC4: benchmark subject execution is still anchored to Chat Completions**
   - Location: `/role-model-router/apps/runtime-host-bridge/src/benchmark-runner.ts`
   - Why it matters: Codex tool-bearing benchmark results still depend on the older compatibility surface rather than the newer Responses tool contract.
5. **RC5: the regression floor does not encode sibling multi-tool or parallel-policy parity**
   - Location: `/role-model-router/packages/provider-openai/test/index.test.ts`, `/role-model-router/apps/runtime-host-bridge/test/index.test.ts`, `/role-model-router/apps/runtime-host-bridge/test/benchmark-runner-judge.test.ts`
   - Why it matters: future regressions could silently reintroduce tool-loss or request-policy drift without failing the current suite.

## Corrective Direction

1. Extend `RuntimeExecutionRequest`, Chat Completions ingress, and Responses ingress so request-side `parallel_tool_calls` can survive as `true`, `false`, or unset.
2. Teach native Codex non-stream transcript normalization to preserve `function_call` items and sibling ordering, then thread those tool calls into downstream non-stream Chat Completions and Responses synthesis.
3. Introduce a Responses-native continuation transformer that can replay assistant tool calls and tool outputs as typed items for native Responses targets while retaining bridge-safe Chat Completions replay for chat/bridge targets.
4. Keep same-provider optimizations such as `previous_response_id` optional and nonportable across route-shape switches.
5. Add a Responses-based benchmark subject path for Codex tool-bearing cases without weakening the runtime’s `/v1/chat/completions` compatibility obligation.
6. Add RED-first regressions for sibling multi-tool parity, `parallel_tool_calls`, route-switch rendering, and benchmark subject migration before any production changes.
