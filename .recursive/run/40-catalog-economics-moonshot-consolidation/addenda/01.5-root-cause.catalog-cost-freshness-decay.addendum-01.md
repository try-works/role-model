## Symptom

After SEA rebuild from run 40 worktree (`351bcce`), Tier 3 operator probe on `:3456` **failed**:

Automated unit tests (synthetic fixtures, fresh profiles) **passed** — gap was live-operator profile shape only.

## Root cause

`getCostMetric()` in `packages/core/src/router.ts` correctly computed catalog-derived `observedValue` (local-free → `1.0`, Kimi → lower), but then applied **`decayToNeutral()`** using observed-profile **freshness weight** when `observedDataConfig.enabled`.

On the operator baseline:

- Local peer telemetry is **stale** (low freshness weight)
- Kimi telemetry is **fresher**
- Decayed local cost metric ≈ **0.501** (neutral-ward); Kimi ≈ **0.582**
- Kimi won total score despite catalog economics marking local as `local-free`

This violates **R6** (cost strategy prefers local-free when eligible) and **R7** (catalog rates must not be distorted by stale telemetry freshness).

## Why unit tests missed it initially

Phase 3 routing tests used synthetic observed profiles without the stale-local / fresh-remote asymmetry seen on `%LOCALAPPDATA%\Role Model Runtime\` operator memory. The catalog overlay and `tokenEconomicsSource=local-free` were correct; only the router-core freshness decay on the **catalog cost metric** was wrong.

## Fix direction

- Catalog-derived cost metrics must **not** pass through `decayToNeutral()` — fixed rate tables are independent of observed-profile freshness (R6/R7)
- Add regression test with stale local profile + fresh Kimi profile asserting local catalog cost value stays **1.0**
- Rebuild SEA from worktree; restart `:3456` with quoted `--runtime-state-root` (path contains spaces)
